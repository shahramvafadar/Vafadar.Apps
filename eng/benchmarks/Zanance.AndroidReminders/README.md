# Independent Android cold-reminder qualification

This project compiles the original production application, storage host, reminder service, native scheduler,
resources and AOT profile under `pro.vafadar.zanance.androidreminderreview`. Production never references it.
It has no portable recovery credentials, network clients, authentication shortcut or financial posting.

Build a complete signed offline Release package with `eng/scripts/Build-AndroidApk.ps1 -Offline -Project
eng/benchmarks/Zanance.AndroidReminders/Vafadar.Zanance.AndroidReminders.csproj -Output <owned-output>`.
An explicit `review_run` containing 32 lowercase hexadecimal characters initializes exactly one fictitious
account/unpaid plan, retaining its original marker and identities after an interruption. Native permission
comes from the ordinary platform dialog. No OS settings or device clock changes are allowed.

The read-only URI `content://pro.vafadar.zanance.androidreminderreview.status/status` returns only the synthetic
run, process/window count, publication state, snooze counts and populated-fixture preservation. It never
prepares storage, creates a window or returns keys, database bytes, notifications or preference payloads.
Observe the original plugin notification action in a deliberately cold independent process, then query
its original PID before opening another activity. Retain failed/live evidence rather than restarting on
observation timeout. A false `financialMatch` while `protected` is false means no financial read was attempted;
it does not report a financial difference. Build-time and activity/query guards reject a changed identity
before window creation or synthetic state reads. Provider initialization itself stays constant and does not
resolve native context, services or storage. Native action qualification and its limits are recorded
in `src/Apps/Zanance/docs/quality/cold-protected-reminder-startup.md`; unit proof alone does not establish
native action/lifetime success.
