# Protected household journal process qualification

Independent Windows-only fictional native caller. It reuses the existing original protected factory helper,
current-user DPAPI generation keys and the reviewed source-built SQLCipher package. It never opens the main app,
an owner database or another project's resource. No network request is made; room/session identities are explicitly
fictional, so this does not replace actual service authorization/financial/phone acceptance.

Use a fresh owned path under `artifacts/household-journal/`. `prepare` proves refusal of an unregistered plaintext
factory, commits the original device/root/candidate epoch and literal membership request to actual protected
storage, checks that portable memory export strips every new household authority table/private frame while the
original remains intact, then deliberately terminates the process with exit23 without unwinding its owning
factory/generation/key scopes. `resume` reopens the exact same native files/keys in a distinct process, validates
the same commitments and literal request, verifies/promotes the signed membership's original key, opens its
original encrypted grant and checks cross-identity refusal. Missing/corrupt state is preserved/refused, never reset.

Following that exact retained fixture, `financial-prepare` freezes the original financial outbox, seals/journals
the exact operation/attempt/cutoff/ciphertext, keeps a later original edit outside it and begins a separately
verified inbox without publishing incomplete finance. It deliberately exits23. `financial-resume` reads the
same original keys/ciphertext, refuses a corrupt event and premature cutoff retirement, completes the verified
inbox and exits23. `financial-cold` replays the committed inbox in another process and checks that the newer
original edit remains local and no network acknowledgement was invented. Receipts in these modes are explicitly
synthetic; actual protected HTTP/PostgreSQL acknowledgement/restart qualification lives in `../HouseholdRoundtrip`.

The original `d294-keys` financial preparation exposed a mismatched512KiB generic parser ceiling versus its2MiB
ciphertext-metadata caller. The failure and same-fixture continuation were retained. The generic ceiling now
supports2MiB public ciphertext metadata; each signing/decryption caller retains its smaller explicit limit.
No key, financial file or ciphertext was regenerated to hide this failure. This interrupted fixture did not
complete every first-phase partial-prefix assertion; use the actual HTTP qualification for that accepted path.

This covers completed-transaction process loss only, not mid-transaction/power-loss durability, Android/iOS,
hardware-key assurance, main household registration or release acceptance.
Private source/output buffers are not printed and the retained fictional fixture is not uploaded.
