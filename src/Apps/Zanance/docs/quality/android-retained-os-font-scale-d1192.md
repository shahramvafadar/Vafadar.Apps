## Scoped configuration handling

MainActivity now declares FontScale handling and captures the actual initial
font scale alongside density. A positive changed font scale reapplies original
public handler font mappings and invalidates measurement while retaining the
open page. Android's native SP conversion remains responsible for text scaling;
no old-pixel ratio, guessed font size or global font policy is introduced.

Font-only changes do not remap explicit minimum dimensions or stock Entry
background/padding. Those existing operations remain conditional on a real
density change. The existing current-window/root checks before/after callbacks
remain intact, as do custom ownership restrictions. No schema/model, financial
command, localization text, palette, runtime, GC or key policy changes.

The first corrected complete APK retains the draft, focus and Step3 at both
font scales in PID5476, but its large-font XML shows only15visible pixels of the
input at the ScrollView bottom. That partial result is not layout acceptance.
The original final assertion also required exactly the previous absolute Y

offset to keep a focused control visible. That overstrict positional assertion
is retained and replaced by the actual target/viewport requirement, not by
discarding the real15pixel failure. All raw first-candidate packets remain.

The additional correction asks native ancestors to reveal the same focused
control after the new layout, before drawing. Its one-draw/detach listener holds
only weak Activity/window/root/focus owners. It rechecks the original current
root, focus, attachment and active native window before requesting the actual
native rectangle. It does not change text/focus, invoke a command, switch page or
retain an old control after root retirement. Font-only changes still avoid the
separate density minimum/background/padding path.
