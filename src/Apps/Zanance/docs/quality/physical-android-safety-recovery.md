# Physical Android safety-copy recovery (D-312)

## Original observation and complete fix

The approved Samsung SM-A176B installed the complete D-311 Release candidate without resetting data.
The initial System UI observation was not authentication evidence: later bounded policy inspection reported
no secure/showing keyguard. Waking the device and reopening the same process (20935) required no credential.
The owner did not need to be present. No system setting, personal account or personal record was changed.

Fresh onboarding completed without an online identity; the reminder explanation was declined with Not now,
without opening or changing an OS permission. The only initial financial account is explicitly fictitious.
Original native forms saved EUR 1000 income, 25.50 food spending, 5.50 linked partial refund and a EUR 100
transfer to a second zero-opening cash account with EUR 1 source fee. Home moved through 1000, 974.50,
980 and 979; the original ledger displayed Salary/Food/Refund relationships. These are actual device writes,
not an emulator or a duplicated financial algorithm.

The original automatic device-only copy from initial setup was selected through the actual page and explicit
replacement confirmation. The same process returned to the initial zero-balance state. This exposed a real
usability defect: the pre-replacement safety copy was retained privately, but the original page listed only
portable exports and automatic copies, so it could not be selected to recover the later fictitious records.

The page now has a separate translated list of current-context pre-restore safety candidates. Native host
discovery captures the original profile/installation under drained storage ownership. It reads only 52 nonsecret
header bytes from exact bounded opaque safety filenames, without opening, preparing or replacing a key and
without decrypting package content. Automatic copies remain a different cohort. Header matches are explicitly
only candidates: selection reuses the original complete envelope authentication, package validation, preview,
access check and replacement confirmation. There is no share action or portable-export claim for these files.
Foreign profile/installations and invalid/partial/oversized headers are omitted. Unknown/failed files stay intact.
No cryptographic format, financial schema, retention rule, key or database migration changes.
