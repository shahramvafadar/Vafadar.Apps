# Original backup workspace and destination ownership (D-657)

## Change and acceptance boundary

Backup discovery now keeps the original page/root/file, cancellation, row reference,
disclosed language and stable provider/account identity through read and native consent.
An independent command lifetime blocks departure during a sensitive destination command,
even if shared busy feedback changes. A pending readonly discovery can still be cancelled
by Back. A late non-cooperative provider result cannot publish after cancellation.
Discovery continues to span this application's profile sets; retention remains profile-bound.

Local, automatic, safety and connected lists publish only after their original source
read completes. Loading and read failures cover stale controls; explicit Retry obtains
a fresh original snapshot. Raw portable input is retained. Connect, Disconnect, Open
and Delete use the actual captured account identity rather than a display label or a
same-provider replacement row. Storage validates identity before effects and after
readonly results, disposing an unpublished opened stream on failure. Actual successful
effects are recorded before fallible publication. A confirmed deletion's receipt remains
visible in a separate footer when subsequent discovery requires explicit reload.

The original backup writer, encryption, retention, remote adapter and financial schema
are unchanged. These guards do not establish atomic remote token/account transport or
genuine provider authentication. No additional permission or financial operation is added.
