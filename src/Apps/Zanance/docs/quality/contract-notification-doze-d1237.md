# Contract reminder delivery during Android Doze

The calendar boundary correction in [D1236](reminder-date-boundaries-d1236.md) had managed planner evidence. This follow-up exercised delivery of the resulting valid contract reminder through Android's notification service. The fresh API 36 x86_64 emulator had 4,096-byte pages. The independent Android component used the current contract planner, original notification scheduler and pinned Android notification replacement from the repository. It had no financial store, network permission or exact-alarm permission.

Android initially reported the component's notification permission denied. The original scheduler reported disabled and the SDK pending list was empty. The scoped test grant applied only to the fresh component UID. The first arm intent brought the permission-check activity forward without running its arm code. Before continuing, the observer found the original activity, no arm receipt, no pending alarm and no active notification. A fresh activity then performed the sole effective arming. The component build also retained an initial fixture compilation refusal for trying to set a read-only entity ID. The final build passed with zero warnings and errors.

The input contained an expired cancellation deadline at the earliest supported date and one future contract review. The planner returned exactly the review reminder. The original scheduler accepted notification ID 1152437513 under UID 10216 and Android recorded one RTC_WAKEUP alarm for its ScheduledAlarmReceiver. Android's alarm record reported a roughly 74-second inexact window. The emulator entered forced deep Doze before the scheduled time using the [Android Doze test procedure](https://developer.android.com/training/monitoring-device-state/doze-standby).

The device scheduled the notice for 09:24:46.214 local time. The last empty sample was at 09:25:59. The first sample with the active notification was at 09:26:13, about 87 seconds after the requested time. Android still reported deep IDLE in that sample and returned the matching package, UID and notification ID. The sample bounds the observation and does not measure the publication instant. After exit, the same notification was uniquely active with the expected synthetic title and body, and the original wake-up alarm was no longer pending. No tap or snooze was used.

The test restored active power state and reset the battery simulation, then removed the fresh component and verified its active notification was absent. The fixture was then retired with the official emulator tool. Actual AVD and INI absence and a successful build cleanup were verified. The copied retirement helper printed its old read-only cohort label, so verification used the current package removal and AVD receipts. The original Samsung transfer result and the versions and data of both physical phones were preserved. Existing successful delivery scenarios and financial writes were not repeated. The APK and scoped native records remain in the local d1237-contract-notice evidence folder. This verifies one contract reminder during forced Doze on the emulator. The original Plans permission banner and real OEM scheduling policies require their own evidence.
