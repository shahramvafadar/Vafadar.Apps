# Original holding history deletion and short Undo (D-414)

## Reproduced boundary and complete change

Four actual application/SQLite regressions reproduce unsafe original behavior: Undo lost an explicitly
linked fee refund, accepted a mutated deleted quantity, could insert into another actual file with
matching identities, and could make a changed quantity history negative. The first foreign-file
specimen encountered an unrelated missing-category foreign key; adding the original category identity
to that independent target and rerunning only that case reproduced the actual unbound insertion.
Neither that specimen error nor any later observer error is product acceptance.

HoldingDeletionReceipt binds the original immutable group to the actual file, complete type history/
prices/locations, affected accounts/categories, explicit retained refund rows, absent money/group
identities and orphan attachment ownership/content digests. The existing actual-file writer captures
before/after facts and rejects changed source, currencies, refunds, content, missing receipts, foreign
files, consumed authority and caller mutation before restoration. It restores copies, rechecks domain
quantity history, relinks only the original explicit refunds and validates the complete original
packet again before commit. Restored rows may advance UpdatedAt; original creation and financial/
attachment metadata remain. A rejected claim cannot reset a consumed receipt. Shared money groups
owned by another holding event refuse deletion instead of guessing ownership.

Deletion reads its original row/group/dependents coherently from the same displayed type/history/
price packet. The existing delete writer rechecks original facts and pending native ownership under
fresh commercial/household rights. Its typed committed result retains the exact Undo receipt even if
Changed fails. Undo similarly distinguishes accepted restoration from failed following notification.
No schema/model, storage scale, money sign, fee/refund meaning, price history, permission or network
provider is changed. Original standalone refunds remain recorded/unlinked during deletion, then regain
only their original link through a valid Undo. Existing startup orphan cleanup and short-offer lifetime
remain; this is not a durable Undo across process death.

The actual HoldingHistoryEditor uses original edit/delete actions and explicit deletion confirmation,
including linked payments/fees and retained refunds. Source changes require Refresh; cancellation
writes nothing. A failed uncommitted Undo retains its offer for explicit retry, including owner
departure. Known acceptance retires the original action before fallible readback; accepted Undo cannot
be resubmitted. Parent/tab departure retires pending ownership. Feedback, Undo and Refresh remain in
the fixed growing footer outside the history viewport; nine captions have real six-language texts.
The separate inline manual-price draft is retained.
