# Original plan monetary context - D-430

## Scope and implementation

Each original source/destination input captures its known ISO currency, immutable parsing culture
and explicit display-unit record. The central MoneyText parser/formatter accepts that explicit unit;
existing ambient overloads retain their previous behavior. A formatting change preserves raw text
and its original parser, with a complete example beside the field. A currency or unit change retains
the original label, disables Save and requires clearing before actual reentry. Merely appending a
digit cannot acknowledge another monetary meaning. Source and destination are independent; unknown
amounts and hidden destination fields do not post stale money or show irrelevant format notes.

Initial saved/transaction values use the same captured formatter/parser. Read-only original readiness
publication does not replace raw context. A detached submission retains both input identities and
its monetary edit revision through original writer checks. Returning to identical text cannot revive
an earlier pending write. Known acceptance still precedes observers and cannot rearm a saved form.
Ownership is captured before validation feedback, so a synchronous binding/observer edit cannot
attach an earlier parsed amount to a newer raw draft. Persisted reference/settings changes still
follow D-429 source-retirement rules; the monetary guard never relaxes original-source validation.
No schema, migration, compiled model, portable format, permission, provider or SDK changes.
