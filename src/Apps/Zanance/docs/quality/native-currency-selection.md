package pro.vafadar.zanance.androidhomereview. It does not qualify the Samsung USD draft or prove
that arbitrary injected text simulates a user typing. No new Main APK, financial Save, metadata

## Negative evidence and corrected inference

Early300ms first-open samples have unrealized/offscreen rows. Later original-source packets already
show EUR/GBP visible. Active-window-only uiautomator dumps omit this nonfocusable popup; absence in
that dump is not a blank list. Reopening with a default template was confounded with another open;
a later same-original-template control also shows visible rows. Neither proves a template defect.

Two speculative viewport candidates and a native-frame trace are rejected and removed completely.
The trace shows nativeScrollY586 after four frames with no manual scroll-target command. Original
source PID7466 then fails an overstrict raw-name/full-bounds observer. PID8011 proves visible GBP
378x44 and EUR/GBP captions but raw ContentDescription remains null; its final stored-row audit
passes. The final caller reads CreateAccessibilityNodeInfo, observes the actual semantic name and
passes the same original first-open selection. Product presentation has no diff. Earlier observer
refusals and delayed terminal reports remain in private artifacts/currency-input-d423; no accepted
money, seed or successful suite is replayed to replace them. Some older failing observers exit before
stored-row comparison, so only reports that actually contain that comparison claim it.

This narrows the D-422 uncertainty, not the entire device/input gate. Physical USD typing, other
forms/currencies, TalkBack speech, general ANR/crash, wider devices, iOS and release remain separate.
