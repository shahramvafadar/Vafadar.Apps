## New premise, separate from D794

2 November2026. Original PeriodMath.MonthOf(Persian) calls GetYear/GetMonth and DayOf
calls GetDayOfMonth. Original recurrence calls them repeatedly for unchanged rule
start/calendar while generating monthly/yearly candidates and skipped-step bounds.
D794's much larger Persian component cost gives a concrete new inspection input, not
exclusive CPU attribution. Retain original per-step List allocation,400day window,
explicit identity resolution, financial policies and every production source byte.
The rejected D794 value-date representation is not reused or rescued.

A new private per-enumerator Anchor retains only original year/month/day results,
keyed by original Start and Calendar. Each use rechecks both keys; mutation invalidates
the derived pieces. No global/rule-object/shared cache, copied calendar algorithm,
stored date or financial source is introduced. Only Persian Monthly/Yearly selected
at enumerable creation use that private iterator; other calls return the original
iterator directly, including lazy null validation. Caches belong to each enumerator,
including a second enumeration; no mutable-input snapshot is silently substituted.
This is finite equivalence evidence, not thread-safety or all race behavior acceptance.
