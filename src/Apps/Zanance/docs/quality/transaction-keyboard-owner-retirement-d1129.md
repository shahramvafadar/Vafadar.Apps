## Source correction and exception policy

TransactionsKeyboardViewport now releases its own listener and owned padding
when initial layout fails. The original exception stays observable. If cleanup
also throws, an AggregateException preserves both exact exception instances in
initial/cleanup order; a cleanup error cannot replace the original silently.
Existing conditional padding ownership remains: foreign changed padding is not
overwritten merely to manufacture restoration.

TransactionsPage clears the viewport field before invoking Dispose, revokes
publication and detaches Undo before layout cleanup, and deactivates the original
model even when a callback fails. A retirement guard prevents reentrant retained-tab
refresh from reacquiring authority during that operation. It resets on exit, so
a later genuine appearance may still refresh normally. Model and cleanup failures
are both retained when both occur; single exceptions keep their original identity.
The reader, writer, consent, financial payload, schema, window policy and geometry
formula do not change.
