## Original defect and resulting behavior

The old detail loader assigned a header before independent live-store group, holding, refund,
attachment and rule reads finished. A native confirmation could later delete the then-current query;
reviewing resubmitted a retained financial row. A delayed template prompt, document open or receipt
read could outlive the displayed source.

The detail now prepares its actual-file packet in a worker read transaction, validates the complete
source, then publishes every field behind the loading cover. Initial/reload failure keeps a covered
translated read-only Retry. A missing row publishes a distinct empty state. Display reads never
initialize settings. A different routed identity owns a fresh session; retained commands and late
callbacks cannot adopt it. Departure retires the entire packet, including document/receipt work.

Each original action checks cached rights, exact file and current facts. The review writer updates
only the original review flag. Rule creation derives from the original category/match and refuses an
equivalent existing rule. Delete uses the original reviewed group and the existing exact file-bound
short-Undo receipt. Known commits are consumed before fallible notification. Following readback
failure offers read-only recovery, not resubmission. Template creation and OCR continuation preserve
their separate original owners. A refused document dispatch removes only its newly created cache
file; a potentially accepted native request retains the existing startup cleanup policy.
