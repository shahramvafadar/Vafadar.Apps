# OpenAI and Gemini integration plan for Zanance

Reviewed 18 November 2026 against source revision `c2931856`. The owner selected both providers and requested an administrator-controlled switch. This document prepares implementation. Live credentials, budget amounts, customer pricing and production activation have separate acceptance gates.

## Product scope and existing boundary

The first release of this work covers explanation of one recorded personal period and comparison of two explicitly selected personal periods. Reuse the existing six-language client, review/confirmation screens, aggregate calculation, protected storage, source validation and credit journal. The app provides the exact bounded aggregate and destination to the user before confirmation. Its wire input remains `AiPayload v1`, with periods, confirmation scope, counts, currencies and integer minor-unit totals. Shared data, raw ledger rows, names, notes, receipts, PDFs, payment instructions, web grounding and tool calls stay outside this delivery. The finance engine remains the source of all figures. The model explains the disclosed figures and has no authority over data, recommendations linked to payment or write operations.

The [local analysis implementation](15-ai-local-delivery.md) already freezes a quote, reserves credit before dispatch and follows the original request ID thereafter. The current host only maps the analysis routes under the local qualification gate, and its dependency injection still installs `UnconfiguredAiProvider`. The provider/model in `AiOfferRow` alone cannot recover the vendor execution, pricing revision or original project after an administrator changes the default. The current terminal states also lack a separate representation for a vendor-billed attempt with no usable customer result. Both gaps are part of the implementation.

## Administrator switch

- Internally register two adapters behind `IAiProvider` and route through a small registry. Define an immutable approved profile revision with adapter ID, provider project reference, model revision, endpoint and region, storage mode, prompt revision, price revision and token limits. Store only secret references in profile configuration. A provider replacement can implement the existing server contract without a mobile integration.
- Start with one active default profile for the two supported purposes and an Off state. Use an authenticated, audited server-operator command or existing authorized admin mechanism to validate and atomically switch the default. The activation record identifies the previous and new revisions, actor, timestamp and reason. No arbitrary model, URL, credential or raw setting is accepted from a client. Initial delivery includes an operator runbook. A dedicated graphical admin page is a subsequent UI choice.
- Offer creation reads only local settings and technical prices. It has no model or provider call. Bind quotes to the immutable profile and disclosed credit maximum. On submission, an unaccepted quote whose profile retired or whose disclosed terms changed is durably refused without vendor I/O. The client can obtain a new quote, show it and seek fresh confirmation. Preserve the original quote's expiry behavior and apply the decision atomically with reservation under concurrent switches.
- Persist the accepted profile with every new operation. The default pointer is used for new offers only. Switching or disabling new work leaves accepted in-flight requests with the original project, endpoint, model and tariff for status, reconciliation and retention cleanup. Preserve rotated credential access through the same authorized project. If an original destination is unavailable, keep the uncertain operation recoverable and alert the operator. A security stop can explicitly disable further network traffic, with the original unresolved state retained.
- Customer choice can later expose allowlisted display profiles by purpose. The server validates the selection and freezes it in the normal quote. No automatic switch after a failure or a pending result. Customer BYOK, new prices, raw document upload and shared-profile analysis are separate changes.

## Durable dispatch, recovery and accounting

1. Preserve the existing per-owner original operation key and consent digest. Add an additive service migration for the frozen profile, dispatch state, opaque vendor operation ID, provider usage and reconciliation evidence. Keep provider transport metadata out of the mobile/local financial database. Test upgrade from existing service rows and the previous app version. Legacy rows use their prior path and are not retroactively assigned to a real provider.
2. Reserve customer units and the maximum vendor cost before the first outbound create. Commit a durable intent that a worker can claim once across process or replica restarts. Track the boundary between an intent definitely not sent and a claimed attempt that could have reached the vendor. A crash or request cancellation after that boundary preserves uncertainty. An expired worker claim alone cannot authorize another create. Existing mobile status calls and a bounded server reconciler observe the same operation without dispatching again. The [isolated pilot recovery](28-ai-synthetic-provider-pilot.md#original-dispatch-recovery) now drains only never-claimed work; independent lost-receipt correlation remains open.
3. Attach a server-generated opaque correlation reference, with no account identity or financial data. Persist the native response/interaction ID as soon as it is returned. Use only authenticated vendor status against the stored original project and ID. For a lost create receipt, qualify independent correlation before enabling real data. Investigate OpenAI signed events plus retrieval of opaque response metadata. For Gemini, qualify the documented signed event mechanism, including a request-scoped server-controlled callback if needed, and independently verify the callback binds to the exact original operation. Verify signatures against the actual body and provider contract, reject replay and foreign project/operation IDs, and deduplicate before settlement. An OpenAI client request ID helps support investigations and supplies no documented deduplication or lookup promise. Do not assume a Gemini POST can be safely replayed either.
4. Keep unresolved outcomes Pending, with no automatic resend, vendor switch, expiry refund or second customer debit. A provider 404, transport timeout, missing callback and missing usage alone prove neither rejection nor zero cost. Add a limited operator reconciliation queue with evidence, aging, retry budget, who/when audit and clear pending state. The isolated [pending queue](28-ai-synthetic-provider-pilot.md#management-panel) shows original request evidence and exposes a status-only check. The server records the actor, time and attempt before the original lookup. The pilot allows three operator checks per request with a minimum one-minute interval from the last lookup. Confirmed provider rejection/no charge releases the original reservation once. If the vendor charged for blocked, malformed or otherwise unusable output, account for the vendor spend separately. Proposed customer policy is to release customer credit on a confirmed unusable result while recording the vendor cost. Approve that rule before billing real users and test the public result/state compatibility.
5. Store usage by vendor and tariff, including billable output/thinking and documented cache components. Reserve using the uncached rate, fixed tier and conservative token ceilings. Use integer billing amounts and explicit rounding. Reconcile the vendor ledger with actual invoices independently from the append-only purchased/gifted customer journal. Reject or review costs beyond the quote without increasing customer debit above the confirmed maximum. Enforce separate per-request, per-user and per-project hard caps at server admission, atomically across concurrent operations. The [synthetic admission ceiling](28-ai-synthetic-provider-pilot.md#synthetic-vendor-cost-ceiling) reserves integer uncached ceilings under the original pilot lock. Actual-charge reconciliation and production tariffs remain open. Provider budget alerts supplement these limits.

Published Standard reference prices on 18 November 2026 are USD 2 input and 10 output per million tokens for GPT-6.2 Sol, and USD 1.50 input and 7.50 output for Gemini 4 Hydrogen in Gemini Developer API Paid. At 2,000 input and 500 billable output tokens, that is USD 9 and 6.75 per 1,000 requests respectively, before region or other price differences. These are planning examples. Recheck rates, project availability and exact billing semantics before freezing any live price. The linked OpenAI subscription allowance is vendor-side credit and is independent from Zanance customer units. Start pilot projects with an independently approved small cap and keep live customer purchases disabled until pricing is approved. ## Privacy, environments and operations

Keep API credentials in separate protected server secret mounts or the approved secret store. The owner provisions credentials personally. Use independent synthetic and production projects, least-privilege service identities and an outbound allowlist. Never include provider secrets, payloads, output or raw vendor error bodies in routine telemetry. Log opaque operation correlation, route revision, error category, latency, billed usage and state transitions. Redact sensitive vendor metadata from the operator surface. User deletion and retention procedures must cover the existing protected service fields and vendor-stored responses where supported. Model safety status is distinct from data retention and cost.

Keep local qualification as-is. Add a separately reviewed, default-off server activation boundary for genuine providers. Hosted customer activation requires a suitable contract, DPA where applicable, approved endpoint/processing geography, authorized retention, verified training/sharing settings, and deletion/recovery rehearsal for the actual project and endpoint. For OpenAI, check eligibility for the intended EU endpoint or retention controls and test the chosen treatment of background storage. For Gemini, Paid Services in the EEA and the ability to select a region are distinct. If the Developer API profile cannot meet the production requirements, evaluate the approved regional Google Cloud profile end to end. Do not transfer the Developer API's pricing, operation recovery or retention assumptions to the Google Cloud profile.

## Implementation sequence and release evidence

| Phase | Deliverable and exit condition |
|---|---|
| 1. Provider capability pilot | Synthetic calls in separate approved projects. Record model and request schema, returned IDs and usage, lost create receipt recovery, signing and duplicate events, and retention/deletion and status limits. Compare a shared synthetic corpus in all six app languages for numerical fidelity, scope, safety, output validity, latency and actual cost. Include multi-currency totals, refunds, no-data and period comparisons. Require zero incorrect published totals, currency mixes or unsupported statements in the accepted evaluation corpus. Record p50/p95 latency, refusal rate and measured cost per completed result, and set their operating limits before real-data activation. |
| 2. Server routing and durable accounting | Implement profile registry, operator switch, additive migration, immutable offer binding, single-dispatch claim, reconciliation and server budget limits. Use fake transports and isolated PostgreSQL for deterministic failures before connecting real providers. |
| 3. Two live adapters in the isolated lane | Wire OpenAI and Gemini independently. Check both normal completions, storage and deletion, auth/invalid model, refusal/bad result, billing evidence and failure handling. Retain evidence without credentials or personal content. |
| 4. Integrated switch acceptance | Exercise both directions and Off via the original app and hosted API in the isolated environment. Cover old quote before acceptance, switch during a pending request, pricing/model change, concurrent holds and caps, restart at every dispatch boundary, lost acknowledgement, duplicate webhook/receipt and rotation. Old requests follow the original route, there is one terminal settlement, and financial data remains unchanged. Verify the existing minimum-offline build remains offline. Qualify the appropriate connected test package. Run only new and directly affected checks, plus any release-mandated checks. |
| 5. Controlled activation | Operator runbook documents setup, health without customer payload, switch, stop, rollback and pending drain. Admit each real-data profile separately only after its privacy, recovery, budget and customer pricing checks pass. If either adapter cannot recover an ambiguous accepted request, keep that profile in the synthetic lane until the gap is resolved. |

Working estimate for phases 1–4 is 35–55 engineering hours, assuming both official endpoints provide usable recovery and project prerequisites are ready. An alternate regional endpoint, unresolved lost acknowledgement, external privacy review or public activation can extend that estimate. No implementation, deployment, account change or live model test was performed for this plan.
